# 统一机器人 API v1

**状态：** 探索性实现协议  
**范围：** 厂商中立的机器人 SDK 与后端适配器协议  
**日期：** 2026-10-12

## 目标

为跨厂商机器人的应用、Policy 和使用工具的语言模型提供一套语义 API。Hardware Package 可以将该 API 转换为 ROS、厂商 SDK、原生库或网络协议。公共 API 名称只描述功能和单位，绝不体现制造商或其中间件。

该协议由能力驱动：机器人报告其实现了哪些观测和动作。应用可以在选择动作前检查这些能力。后端可以只实现能力子集；不支持的操作应返回类型化的“不支持”结果，不得在不告知调用者的情况下重新解释操作。

## 公共模型

### Robot 与生命周期

`Robot` 是面向用户的操作句柄。它提供：

- `robot.capabilities()` — 设备、状态字段、动作模式、单位、边界和支持的频率。
- `robot.state()` — 最新的聚合 `RobotState`；如需包含源时间戳的设备实测状态，应使用 `get_joint_state(device_id)`。
- `robot.get_joint_state(device_id)` — 实测的具名关节位置和新鲜度状态。
- `robot.move_joints(device_id, positions)` — 完整的具名绝对关节目标，以及一个 `CommandResult`。
- `robot.command(Action)` — 提交类型化动作并接收一个 `CommandResult`。
- `robot.lifecycle.connect()`、`enable()`、`disable()` 和 `stop()` — 显式的生命周期操作。

适配器负责后端连接和转换。通用 SDK 负责共享协议类型、兼容性检查、动作映射、安全策略和结果归一化。

### 状态与单位

- 旋转关节的位置和速度分别使用弧度和弧度/秒；力矩使用牛顿米。
- 笛卡尔平移使用米。姿态使用按 `x, y, z, w` 顺序排列的归一化四元数。每个位姿都有明确的参考坐标系和源时间戳。当前 `Pose` 尚未携带自身的时间戳，因此本协议尚未完全实现。
- 关节值以稳定的规范关节名称为键；调用者不依赖数组顺序。后端在其边界处完成所有顺序转换。
- 存在关节级状态时，灵巧手或夹爪状态表示为具名关节。只有本体清单定义了有意义的映射时，才公开标量开口度/夹爪值。
- 缺失的观测保持缺失，不根据命令合成。可选的触觉、力、温度和设备健康通道保留类型化名称及源时间戳。
- `SafetyState` 独立于命令完成状态，分别报告启用状态、急停状态、故障以及各设备状态。

### 动作模式

v1 的语义动作词汇如下：

| 动作 | 目标与载荷 | 规范语义 |
|---|---|---|
| `joint_position` | 一个设备；具名关节 → 位置映射 | 以声明的规范单位表示的绝对关节目标 |
| `cartesian_pose` | 一个末端执行器；`Pose` 和坐标系 | 指定坐标系中的绝对末端执行器目标 |
| `joint_trajectory` | 一个或多个设备；带时间戳的具名关节目标 | 按时间索引的位置轨迹；单位同上 |
| `gripper_position` | 一个夹爪；范围为 `[0, 1]` 的标量 | `0` 表示完全闭合，`1` 表示完全张开；仅在清单中完成标定后可用 |
| `hand_preset` | 一只灵巧手；来自已声明能力的具名预设 | 执行已声明的语义抓取/张开预设 |
| `stop` | 设备或整台机器人 | 请求取消/停止运动并报告确认结果 |
| `set_enabled` | 设备或整台机器人；布尔值 | 更改执行器启用状态并报告服务结果 |

单设备动作是基础原语。协调多设备运动时，使用包含具名设备动作的组合目标，在不编码“26 个值”等特定于模型的拼接向量的同时，保留同步意图。如果后端无法协调多个设备，可以拒绝该组合操作。

`cartesian_pose` 是目标动作；对于明确声明增量控制协议的 Policy，仍可使用 `ee_delta`。绝对位姿与增量位姿绝不可混为一谈。

### 能力描述

每个设备都声明：

- 稳定的 `id` 和语义类型（`arm`、`hand`、`gripper`、`base`、`sensor` 等）；
- 规范关节名称、类型、单位和限制；
- 带单位和预期更新频率的状态通道；
- 支持的动作及其载荷 Schema、坐标系、边界和控制频率范围；
- 可选预设和经过标定的映射，例如标量夹爪开口度；
- 是否支持多设备同步。

能力是对运行时事实的描述，而不是从设备类型继承而来的假设。清单声明必须与后端实现一致。能力协商会拒绝未声明的动作。

### 命令结果与错误

`CommandResult` 包含命令 ID、状态、适配器是否已下发请求、消息、后端错误码/详情、时间戳以及可选的最终状态。状态词汇包括 `simulated`、`not_dispatched`、`submitted`、`accepted`、`running`、`succeeded`、`cancelled`、`rejected`、`failed`、`timed_out` 和 `outcome_unknown`。`submitted` 仅表示已发布到本地传输层，并不代表控制器已经确认或运动已经完成。`outcome_unknown` 表示已尝试发送，但无法观测到结果。只提供发布能力的后端不得虚构“已接受”或“已成功”状态。

### 语言模型工具边界

面向 LLM 的工具层应公开一组从 `capabilities()` 派生的精简白名单工具，例如 `get_state`、`move_joints`、`move_end_effector`、`set_hand` 和 `stop`。工具 Schema 使用相同的类型化动作载荷。模型负责选择意图和参数；确定性的 SDK 验证、能力检查以及配置的安全限制共同决定能否下发命令。工具层不开放任意 ROS Topic 发布或原始厂商调用。

## 后端映射规则

1. 在适配器边界转换名称、顺序、单位、坐标系和表示形式。
2. 在 `CommandResult` 中保留后端结果、故障和取消详情。
3. 在确定能力的源信号/命令及其语义之前，不得声明该能力。
4. 仅供后端使用的端点名称和厂商载荷格式应保留在 Hardware Package 内部。
5. 在 Hardware Package 的映射文档中记录不确定的转换；不得在未说明的情况下猜测坐标系或单位。

## 当前实现状态

SDK 已提供 `Robot.capabilities()`、`state()`、`get_joint_state()`、`move_joints()` 和 `command(Action)`。`move_joints()` 要求精确提供设备的全部规范关节名称，并返回一个 `CommandResult`；为保持兼容性，`command(Action)` 仍返回列表结果。公共接口 `Robot.command(Command)` 会拒绝原始后端命令，`Runtime` 现在也使用经过检查的 `Action` 路径。下发前会检查关节边界、数值有限性以及新鲜的启用状态。此前任意设置的单步关节位置上限已被移除。加载本体清单时会合并包级安全值。

可选的 `ros2_mapped` Runtime 组合厂商中立的 Mapping Engine 与 ROS2 Transport。其首个 Hardware Package 绑定仅覆盖右臂：新鲜的 `ArmState` 关节位置、`ArmMove` 绝对 `MoveJ` 目标、Action 拒绝/失败/超时，以及终态后的实测到位状态。它只公开已映射的右臂动作和状态。`CommandResult.dispatched` 将“已尝试发送”与“Action 目标已接受”分别记录；Action 超时会保留物理结果未知这一事实。本阶段没有实现第二厂商、Python Transport 或 Native Transport。

2026-10-12 的主机侧验收通过映射后的 SDK Runtime 执行了 `Robot.get_joint_state("right_arm")` 和 `Robot.move_joints("right_arm", complete_target)`。系统读取到新鲜的 Idle (104)、无故障七关节状态；规范关节 6 的 `+0.10` rad 目标返回了 Action 状态 4/代码 0，终态后的实测误差为 `0.000147` rad。第二次公共 API 调用返回已记录的起始目标，最大误差为 `0.000145` rad。

2026-10-13，Demo 使用相同的公共方法完成了“下降、抬升至示教位姿、旋转前臂两次、回中、下降”这一完整物理动作序列。每个目标都是包含七个关节、以绝对弧度表示的完整映射；每个 Action 结果都经过检查；每一步都要求获得新鲜的实测到位状态后才能继续。这验证了该右臂任务的 Demo → SDK → 映射 → Weiyi → 实测结果路径。

Hardware Package 现在将映射 Runtime 作为唯一的在线控制后端；旧有的厂商特定 Topic 适配器已被移除。映射 Runtime 尚未绑定基于服务的启用/停止、触觉或夹爪语义、笛卡尔控制、左臂以及协调双臂控制。右臂的 `capabilities()` 视图不包含这些动作，也未声明急停信号。

本地机械臂接口构件包括关节和笛卡尔目标、机械臂状态、实时命令、Action，以及上电/拖动/负载/停止服务。映射后的右臂 Action 目标使用观测到的 `MoveJ` 模式，并在 `cart_pose` 中填入六个零；目前未声明任何笛卡尔命令模式或位姿转换。位姿平移单位、旋转顺序和坐标系仍未确认。

本地灵巧手驱动会发布并使用 `JointState`，提供 O6 范围值与弧度的双向转换表，并具备可选的触觉通道。公共 API 对具名关节使用规范弧度；适配器负责与灵巧手的整数命令范围进行双向转换。只有具体实例具有张开/闭合标定时，才声明标量夹爪映射或语义抓取预设。

## 迁移

迁移期间，现有的 `joint_position` 数组和 `bimanual_joint_position` 拼接值仍可读取。新的 SDK 客户端应发送具名值和组合目标。当清单与适配器声明了等价的具名设备动作后，旧有组合模式即进入弃用状态。
