# 机器人接口证据清单

三个本地项目逐字段的完整审计记录维护在 [weiyi-interface-matrix.md](../../../ce-hardware-weiyi-dual-o6/docs/weiyi-interface-matrix.md) 中。该矩阵记录了生成的 ROS 类型、字段、已知单位与限制、端点证据、SDK 映射、置信度以及能力开放门槛。

## 当前证据边界

- 已检查静态源码、生成的 ROS 接口定义、YAML 配置、SDK、适配器和演示程序。离线测试覆盖规范机械臂状态、具名目标排序、O6 端点转换、具名关节安全检查、厂商中立的能力序列化以及命令结果状态。
- 2026-10-12，操作人员提供了来自 `robot_launch` 的主机 ROS 图和状态输出。观测到了右臂状态、SetPower、ArmMove 和 ArmRtCtrl 端点。驱动报告 can2/can3 上共有 18 个执行器在线。这些观测结果验证了端点发现和总线活动，但并未验证所有声明的能力。
- 操作人员报告称，使用绝对关节向量 `[0, 0, 0, 0, 0, 0, 0.02]` 的 `ArmMove` 目标使右臂发生了实际抬升。后续 `ArmState` 显示 `arm_mode: 104`、`NO_FAULT`，且实测关节位置接近该目标。未提供该 Action 的终态结果，因此“已接受”和“已成功”仍是两个相互独立的结论。
- 已提供此前右臂放低时的关节向量，操作人员随后确认，一次直接发送至该向量的绝对 MoveJ 动作使机械臂下降。未提供该直接目标的终态输出和最终实测关节向量。`robot_launch` 示例中具名的 `right_arm_hang` 位姿并不一致，因此不将任何示例位姿视为经过标定的归位姿态。
- 当前在线主机会话具备 ROS 2；Codex 沙箱无法直接操作该 ROS 图。尚未验证 SDK 到硬件的集成，也未验证由 LLM 驱动的物理运动。

## 需要跨项目实现的缺口

1. 机械臂命令发布器在发送关节命令时，以六个零填充 `ArmRtCtrlCmd.arm_pose`；该字段的含义以及 ArmRtCtrl 所需的 Action 生命周期均**尚未确认**。
2. 已通过 ArmMove 实际观测到 `MoveJ`，且一个受限目标返回了状态 `4` / 代码 `0`，实测位置也已稳定。操作人员确认机械臂直接返回成功，但未提供其终态输出。一般情况下的持续时间、速度、取消和失败行为仍**尚未确认**。笛卡尔位姿的单位、顺序和坐标系仍**尚未确认**。在线 ROS 图已验证右侧 `SetPower` 服务名称；所提供的服务列表中不存在 `StopMove`。
3. 已发布的运行时配置中存在机械臂关节软限制，但 SDK 的本体清单尚未表示这些限制。
4. 灵巧手状态包含设备计数值形式的位置以及经过速度整形的数值；适配器映射了位置，但忽略源名称、速度和力矩。灵巧手驱动以零填充 `JointState.effort`。
5. 灵巧手源码中存在可选的触觉接口，但适配器未订阅这些接口；尚未确定已安装传感器的存在情况，以及主要触觉数据的单位和顺序。
6. 清单静态声明了机械臂关节/末端执行器和急停能力，但这些能力尚未通过活跃控制器生命周期、经过验证的笛卡尔映射或急停反馈路径进行验证。
7. 由 26 个值组成的组合动作被拆分为多次独立的发布调用；尚未建立同步组合/事务协议。
8. `Robot.command(Command)` 绕过了 Action 层的能力和安全验证；适配器本地的 enable 并非物理 SetPower；生命周期 stop 也并非运动停止。
9. 演示任务只是就绪检查，无法连接到运行时主机进程来执行 Policy 循环。

有关风险排序、涉及文件和验收门槛，请参阅 [weiyi-interface-implementation-plan.md](../../../ce-hardware-weiyi-dual-o6/docs/weiyi-interface-implementation-plan.md)。
