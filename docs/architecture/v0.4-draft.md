## 1. 背景与目标

v0.3 已提出统一生命周期、Driver Host，以及 `ce up` / `ce down` 的启动和关闭闭环。
当前 WY 接入路径主要完成了原始资产交付、关节状态读取和关节运动映射，但启动
Driver、准备 ROS 环境、硬件使能仍需调用者手动执行厂商相关命令。

v0.4 应让应用通过统一 SDK 使用硬件包声明的运行能力，将厂商端点、运行环境和
启动细节留在硬件包与后端实现中。连接和使能保持显式，不能因构造 Robot 对象而
触发硬件操作。

本文记录已确认的设计方向，并列出尚需细化的契约，不冻结全部接口签名或配置格式。

## 2. 职责划分

| 组件 | 定位 | 责任 |
| --- | --- | --- |
| Robot | 面向应用的机器人操作句柄 | 持有配置，提供能力查询、状态读取、运动命令及便捷连接入口 |
| Lifecycle | Robot 内部的生命周期管理器 | 管理配置、连接、使能、停用和资源释放的顺序、本地状态及重复调用 |
| Adapter | 硬件包内的具体后端实现 | 实现厂商生命周期、状态、命令和能力映射，使用包内资产，解释执行结果与实测状态 |
| Transport | 通用通信机制 | 提供订阅、Action、Service 等通信操作，报告通信结果，不解释厂商控制语义 |
| Driver Host | 运行环境与进程隔离边界 | 承载后端通信与厂商依赖，管理受管 Driver，隔离 ROS、Python 和原生库环境 |
| Hardware Package | 型号级硬件交付单元 | 携带具体 Adapter、厂商接口、Driver、环境要求、启动配置、模型及验证资源 |

Robot 与 Lifecycle 是组合关系。Robot 不再独立维护第二套生命周期状态；例如
`Robot.connect()` 只委托给 `Lifecycle.connect()`。Lifecycle 负责调度，Adapter
负责落实后端行为。

Lifecycle 的本地记录不能替代真实硬件状态。设备可能被外部操作或发生故障，是否
已使能、是否就绪必须结合新鲜的实测状态判断。

## 3. 初始化时完成配置，不公开 Robot.configure()

确认采用以下方向：

1. `Robot.__init__()` 创建 Lifecycle 后，调用 `self.lifecycle.configure()`。
2. 不新增面向应用的 `Robot.configure()` 入口；调用者无需显式执行配置步骤。
3. `Lifecycle.configure()` 作为内部配置阶段保留，并保证重复调用不会重复产生副作用。
4. 配置失败时，构造过程直接抛出明确异常，不返回可用的半初始化 Robot。

初始化允许完成：

- 解析、保存并校验机器人配置和运行选项。
- 检查包内资源路径和必要的静态平台要求。
- 准备后端运行描述、子进程环境参数和启动参数。
- 创建尚未连接硬件的后端与 Host 客户端对象。

初始化不得执行：

- 启动 Driver 或其他硬件通信进程。
- 连接机器人、创建用于硬件通信的 ROS 节点或发送服务/运动请求。
- 使能、下电或改变控制器状态。
- 修改当前进程的全局环境，例如注入厂商 `sys.path`、`PYTHONPATH` 或
  `LD_LIBRARY_PATH`。

“环境配置放在初始化”指准备后续 Host 使用的环境描述，不是在 Demo 进程中执行
厂商环境脚本或加载整套 ROS 通信运行时。必要的进程启动和动态运行检查留给连接阶段。

## 4. 连接是独立的显式操作

保留 `Robot.connect()` 作为便捷入口，实际流程交给 Lifecycle：

```text
Robot.connect()
    → Lifecycle.connect()
        → 确保配置阶段完成
        → Adapter.connect()
            → 启动受管 Driver，或接入已有 Driver
            → 建立通信
            → 等待所需端点和有效状态
```

连接不隐式使能。必须区分通信连接成功、控制器已使能和动作执行就绪，避免要求
`connect()` 先等待已使能状态，再通过 SDK 执行使能的循环依赖。

- `CONNECTED`：通信链路建立，能够获得所需的有效状态；允许硬件尚未使能。
- `ENABLED`：控制器使能已得到确认。
- `READY`：满足目标能力的执行前置条件；仍需在命令下发时重新检查。

Adapter 的连接实现必须在失败时清理部分创建的资源，避免留下半连接状态。具体
超时、重试、并发调用和失败恢复策略在后续详细设计中定义。

## 5. 使能与停用必须落实到硬件

保留显式 `robot.lifecycle.enable()` 和 `disable()`。两者要求已经连接硬件，不能
仅修改本地布尔值，也不能用“设备已经 ready”的检查代替真正的使能操作。

后端应执行以下流程：

```text
统一生命周期请求
    → 硬件包内 Adapter 的厂商映射实现
    → 执行请求并检查响应
    → 等待新鲜的实测状态确认
    → 返回结果或明确失败
```

对于 WY，已知右臂使能涉及 `SetPower` 服务和后续状态确认；这些端点、请求字段和
模式值属于硬件包。下电后的确认语义需要单独验证，不能只把请求中的布尔值改为
`false` 就宣称已完成停用。

不支持的生命周期能力必须明确报告，不能用空实现表示成功。SDK 提供通用通信和
生命周期调度；具体请求、响应解释与状态确认由包内 Adapter 实现，不得在 Core 中
加入 WY 端点或模式值特判。Adapter 可以使用包内配置，但不要求所有厂商行为都通过
SDK 内置的统一 YAML 解释器表达。

## 6. 关闭、停用与运动停止分别定义

本轮讨论采用以下语义方向：

- `close()` 释放本 SDK 句柄持有的连接和资源，不隐式使硬件下电。
- `disable()` 是显式硬件状态变更，需要后端执行和确认。
- 停止运动是独立能力，断开通信、结束进程或下电不能直接当作运动停止成功。
- 清理受管 Driver 时，只处理当前运行实例拥有的进程；不能结束外部启动的 Driver。

受管 Driver 的退出条件、运行中关闭的处理、上下文管理器异常退出策略，以及
`Lifecycle.stop()`、`ce down` 与上述语义的兼容关系，需要在 v0.4 中进一步明确。
特别是 v0.3 的 `ce down` 包含 safe stop 和 disable，不能直接等同于这里的 `close()`。

## 7. 环境隔离与 Driver 管理

目标结构为：

```text
Demo 独立 Python 环境
    │
    │ 厂商中立的 Driver Protocol / IPC
    ▼
Driver Host 的后端运行环境
    ├── 硬件包内的具体 Adapter 实现
    ├── ROS2 Transport / 其他 Transport
    ├── 厂商接口类型与原生依赖
    └── 厂商 Driver
```

Demo 不应依赖手动向自身环境注入厂商路径。硬件包声明运行要求和启动方式，SDK
在连接阶段据此创建或接入 Host。进程隔离不自动等于完整容器隔离；系统依赖如何
安装和固定版本仍需定义。

Driver 管理需显式区分：

- `external`：接入已经运行的 Driver，不拥有其进程。
- `managed`：由 SDK 启动并管理 Driver，记录进程所有权并负责相应资源清理。

上述为语义名称，具体配置字段、默认模式和 Host 协议尚待设计。

## 8. 接口示意

以下代码只表达职责和调用顺序，不是可直接替换现有类的完整实现：

```python
class Robot:
    def __init__(self, adapter, manifest):
        self.adapter = adapter
        self.manifest = manifest
        self.lifecycle = Lifecycle(adapter)
        self.lifecycle.configure()

    def connect(self):
        self.lifecycle.connect()
        return self

    def close(self):
        self.lifecycle.close()
```

应用使用方式示意：

```python
robot = Robot.from_instance(
    "lab/weiyi-right-arm-01",
    allow_motion=True,
)

robot.connect()  # 配置已初始化；此处显式建立硬件连接。
try:
    robot.lifecycle.enable()  # 显式使能并验证实测状态。
    state = robot.get_joint_state("right_arm")
    # 按已声明能力发送动作，并检查 CommandResult。
    # 正常任务结束时，按现场规程显式执行 disable()。
finally:
    robot.close()  # 释放连接；不代表运动已停止或硬件已下电。
```

`allow_motion=True` 只表示允许 SDK 下发运动，不能替代硬件使能或状态检查。

## 9. SDK 与硬件包的架构调整方向

### 9.1 现有结构的问题与目标

重构前的 `MappedRos2Adapter + InterfaceMappingEngine` 在 SDK 中解释硬件包的映射 YAML。
SDK 没有直接写死 WY 字段，但具体适配能力受 SDK 映射引擎所支持的操作和规则限制。
WY 包主要提供资产和配置，缺少可独立演进的具体 Adapter 实现；新增厂商服务、特殊
运动模式或确认流程时，容易要求修改 SDK 才能完成适配。

确认采用的方向是：SDK 提供通用类、统一协议与运行基础设施；硬件包提供可执行的
具体 Adapter，管理厂商资产的使用并实现具体映射。目标是新增一种机器人时，主要
修改该机器人的硬件包；只有统一协议缺少通用能力时才扩展 SDK。

考虑过的组织方式：

| 方式 | 特点与取舍 |
| --- | --- |
| SDK 统一解释 YAML | 简单接口容易描述，但厂商特殊行为受统一解释器限制 |
| 每个包实现完整运行栈 | 独立性高，但通信、线程和进程管理容易重复 |
| 包内具体 Adapter 组合 SDK 通用工具 | 保留厂商实现的独立性，同时复用通用机制；采用此方向 |

不以一个庞大的 `BaseAdapter` 承接现有 `MappedRos2Adapter` 的全部行为。具体 Adapter
实现统一契约，并按需组合通信、进程、状态缓存等工具；通用工具不能隐含厂商语义。

### 9.2 资产、通信与映射的边界

- SDK 包管理负责版本、安装、摘要校验和包内资源路径解析。
- Hardware Package 携带厂商 Driver、接口、库、模型、配置与具体 Adapter 代码。
- Adapter 选择需要的资产、启动参数和环境要求，完成状态解码、命令编码、使能与
  停用、故障解释、能力声明及执行结果确认。
- Transport 负责 ROS 节点、订阅、Action、Service 等机制；不解释 WY 的字段、
  模式值或厂商错误码，也不把通信成功直接认定为硬件动作成功。
- Driver Host / 进程工具负责环境隔离、进程所有权与资源清理；具体 Adapter 提供
  厂商启动方案，复用通用工具执行。只清理当前实例拥有的资源。
- SDK Runtime 保留统一控制约束。Adapter 负责厂商状态与统一状态的转换，不能因
  迁移代码而绕过现有控制授权、状态新鲜度或结果确认要求。

SDK 可以提供关节误差计算和稳定窗口等待等通用工具；某种动作需要哪些反馈才能
确认完成，由 Adapter 根据后端证据决定，不将单一到位流程强制用于所有厂商动作。

厂商接口映射与跨本体映射分别处理：前者属于具体 Adapter；用于策略适配和跨本体
转换的 SDK Runtime 映射继续保留，不能因同名而一起迁出。

### 9.3 SDK 目标目录示意

下列目录仅表达相关模块的目标职责，未展示的现有模块继续保留；文件名不是冻结契约。

```text
src/cross_embodiment/
├── sdk/
│   ├── robot.py               # 面向应用的统一 API
│   └── lifecycle.py           # 生命周期顺序、状态与失败处理
├── protocol/
│   ├── types.py               # Command、JointState、CommandResult 等
│   └── policy.py
├── adapter/
│   ├── protocol.py            # RobotAdapter 契约
│   ├── context.py             # 包路径、实例配置与运行资源上下文
│   ├── health.py              # 统一健康报告
│   └── mock.py
├── transport/
│   ├── protocol.py            # 通信请求、事件和结果
│   └── ros2.py                # 通用 ROS 2 通信实现
├── driver_host/
│   ├── process.py             # 进程启动、所有权与退出清理
│   └── environment.py         # 独立后端环境的准备
├── package/
│   ├── loader.py              # 包内 Adapter 入口加载
│   └── ...                    # 安装、校验、版本与资源解析
├── runtime/
│   ├── installed.py           # 按实例和包入口构造运行对象
│   ├── safety.py              # 通用控制约束
│   └── ...
└── onboarding/                # 硬件包生成与检查
```

`Robot` 与 `Lifecycle` 拆文件以便独立理解，二者组合关系和初始化时内部 configure
的约定保持不变。Adapter 上下文用于提供包路径、实例选项和运行资源，不承担厂商
映射逻辑。隔离模式下，具体 Adapter 与厂商依赖在 Host 中加载，应用侧通过统一
协议访问，不能通过入口加载把整套厂商依赖注入 Demo 进程。

完整 Host IPC 可以分阶段建设；文件移动本身不代表隔离能力已经实现。

### 9.4 WY 硬件包目标目录示意

```text
ce-hardware-weiyi-dual-o6/
├── package.yaml
├── embodiment.yaml
├── adapters/
│   └── ros2/
│       ├── adapter.py         # WeiyiDualO6Adapter，统一接口的具体实现
│       ├── mapping.py         # 关节、单位、状态、命令与错误转换
│       └── driver.py          # WY 启动方案、环境与资产选择
├── config/
│   ├── connection.yaml
│   └── safety.yaml
├── vendor/                    # 原始 Driver、接口与依赖
├── launch/
├── models/                    # 模型的组织位置；迁移须同步清单与摘要
├── examples/
├── tests/
│   ├── test_mapping.py
│   └── test_adapter.py
└── ...                        # 来源、许可、验证记录等交付资源
```

包入口示意为 `adapters.ros2.adapter:WeiyiDualO6Adapter`，由该类实现统一 Adapter
契约。包内先保持少量职责明确的文件，再随规模拆分状态与命令处理；不为每个方法
预先建立独立模块。包内代码应与厂商资产一起纳入版本和完整性校验。

具体方法的职责为：

- `configure()` 校验配置、定位资源并准备运行方案，由 Robot 初始化触发。
- `connect()` 接入外部 Driver 或启动受管 Driver，建立通信并获取有效状态。
- `enable()` / `disable()` 执行 WY 请求并确认实际硬件状态。
- 状态和命令方法实现 WY 接口与统一协议的转换，返回统一结果。
- `capabilities()` 声明当前包、后端与配置实际实现的能力，`health()` 报告真实运行状态。

YAML 仍可作为端点、参数与映射数据的配置形式，但不替代包内可执行 Adapter，也
不要求 SDK 核心理解每一种厂商行为。

### 9.5 现有文件的迁移方向

| 原模块 | 当前处理 |
| --- | --- |
| `driver/ros2_mapped.py`、`mapping/engine.py` | 删除；厂商协议映射由硬件包内 Adapter 实现 |
| `driver/ros2_transport.py`、`backend/protocol.py` | 删除旧路径，统一使用 `transport/ros2.py` 与 `transport/protocol.py` |
| `driver/backend.py` | 删除旧入口，包加载统一使用 `package/loader.py`，且只加载包内代码 |
| `driver/process.py`、`driver/health.py` | 迁入 `driver_host/process.py`、`adapter/health.py` |
| `adapter/base.py` | 删除转发文件，Adapter 契约以 `adapter/protocol.py` 为准 |
| `sdk/robot.py` 中的 Lifecycle | 已拆到 `sdk/lifecycle.py` |
| `runtime/installed.py` | 按硬件包入口构造 Adapter，不再支持 SDK 内置厂商 Adapter |
| Onboarding 生成路径 | 生成硬件包内的 Adapter 骨架和映射证据，不在 SDK 执行厂商 YAML |

迁移顺序建议：

1. 固定 Adapter 契约、构造上下文和运行位置；新版本只接受包内 Adapter 入口。
2. 以 WY 包实现配置、连接、状态、使能、运动与关闭的完整路径。
3. 从该路径提取通用通信、进程与辅助工具。
4. 更新实例工厂、包清单和代码资产校验，接入新包。
5. 让生成工具产出包内 Adapter 实现，并由包作者完成厂商语义和现场验证。

旧 SDK 入口不再保留转发兼容层；使用旧入口的硬件包需要迁移并发布新包版本。离线验收
应覆盖具体映射、生命周期、失败清理和控制约束；硬件验收独立执行。

## 10. 当前实现与后续工作

已落地的基础改动：

- Robot 构造时调用 Lifecycle.configure()，配置失败直接终止构造。
- Robot 不新增公开 configure()；connect() 保持独立并委托给 Lifecycle。
- 配置阶段的无硬件副作用契约已写入 Adapter Protocol；Adapter Protocol 要求 configure()；缺少此方法的实现需迁移。
- 生命周期要求当前 Adapter Protocol；旧 SDK Adapter 入口和旧 YAML 执行引擎已删除。

本轮 SDK 与 WY 包重构的实施状态：

- `sdk/lifecycle.py` 独立调度生命周期；使能要求显式连接，`Robot.close()` 只断开连接，
  不隐式停用。`Lifecycle.stop()` 执行显式停用后关闭，不代表运动停止。
- `adapter/` 提供协议、包资源上下文和健康报告；`transport/` 提供通用通信契约与
  ROS 2 订阅、Action、Service。`driver_host/` 提供子环境、进程管理和 Transport IPC。
- WY `0.2.0` 包入口为 `adapters.ros2.adapter:WeiyiDualO6Adapter`，具体状态、命令、
  模式和结果解释在包内 `mapping.py` 实现；不依赖 SDK Mapping Engine。
- WY 初始化仅准备配置；连接支持 external/managed，并允许尚未使能的有效状态。
  上电请求通过 SetPower 执行，要求请求后的新鲜实测状态确认；失败连接清理部分资源。
- ROS 2 Transport 在独立 Python 子进程中加载厂商环境，应用环境和导入路径不被修改。
  本轮纯 Python WY Adapter 仍在应用侧运行，尚未完成第 7 节的完整 Adapter IPC 隔离。
- 实例加载不再固定注入 ROS 要求或覆盖进程管理选项。包内同名模块按包路径隔离加载。
- 旧 YAML Adapter、映射引擎及转发模块已删除。ROS2 Transport、进程、健康状态和
  包加载器使用各自的新模块路径；包加载器只接受硬件包内部的 Adapter 入口。
- Onboarding 运行包生成包内 `GeneratedAdapter` 骨架和只作证据参考的映射 YAML。
  骨架连接、使能、状态读取和动作调用均明确未实现，需由硬件包作者完成后再做预检。
- WY 下电模式缺少已验证证据，默认 disable() 在下发前明确报不支持。指定已验证的
  disabled_modes 和证据引用后才允许下电并检查对应状态；不能直接将任意非 104 模式当作下电。
- 原始 WY 资产不变，新 Adapter 代码和启动配置纳入包资产摘要。本次删除兼容层后的源码
  仅完成语法编译，尚未运行测试、Driver、ROS 节点或真实硬件。

剩余工作集中在完整 Adapter IPC、把证据映射编译成有实际行为的包内 Adapter、WY 下电
语义验证及现场验收。当前生成的 Adapter 只是安全骨架，不具备硬件运行能力。

后续详细设计应依次覆盖：

1. SDK、包内 Adapter 与 Transport 的契约、构造上下文和入口迁移。
2. 配置阶段契约及构造失败处理，确保初始化不触碰硬件。
3. Driver Host 环境、协议、external/managed 模式和进程所有权。
4. 连接就绪与运动就绪的区分，以及连接失败回滚。
5. 通用服务通信机制，以及包内生命周期请求和实测确认实现；按实际需要定义配置格式。
6. WY 使能/停用映射的证据与现场验证。
7. 关闭、停止和停用的错误处理与兼容迁移。
8. 包生成工具、离线测试、文档更新，以及独立的只读和授权运动验收。

基础验收至少验证：初始化不启动硬件；配置和重复连接幂等；连接不隐式使能；
使能失败不得记录为成功；状态过期不得视为就绪；外部 Driver 不被错误终止；
连接失败无资源遗留；close 不被报告为运动停止或下电完成。

本轮包内 Adapter 重构的离线验证：

- 移除旧 SDK Adapter、映射引擎和导入转发路径后，需要重新执行 SDK 与硬件包检查。
- 生成的 Adapter 骨架不执行硬件行为；其契约检查不能替代厂商映射和 ROS2 集成验证。
- 独立审查发现的 ROS 数组序列化问题已复现并修复；已知 Host 退出时的未派发状态、
  进程退出清理竞态和过期就绪判断均有失败后通过的回归测试。
- 未操作真实 Driver、ROS 节点或机器人；上述结果不替代现场验收。
